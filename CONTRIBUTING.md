# Contributing

Keep changes small, reproducible, and test-backed.

1. Open an issue for non-trivial behavior changes.
2. Add or update a deterministic test before changing the contract when practical.
3. Build with warnings-as-errors.
4. Run the sanitizer preset on Linux.
5. Keep algorithmic code independent from ROS 2 and UI concerns.
6. Describe numerical tolerances and units explicitly in reviews.
